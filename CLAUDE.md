```bash
bun install
bun run dev       # Vite на http://localhost:5173 (порт задан в vite.config.js, браузер открывается сам)
bun run build
bun run preview
bun run lint      # eslint src --fix (см. ниже)
```

## Архитектура

Vue 3 (`<script setup>` + Composition API) SPA: Vite, Pinia, Vue Router, Tailwind CSS 3 (стили — только утилитарные классы в шаблонах). Приложение — тестовое задание «каталог книг и авторов»; **бэкенда нет**, он имитируется в слое `src/api`. Спецификация целевого REST API лежит в `book.yaml` (OpenAPI 3, префикс `/api/v1`), и `src/api` повторяет её контракт: `{ items, pagination: { total, page, per_page, total_pages } }`, книги принимают `author_ids`, ошибки — `ApiError` с `errors: [{ field, message }]`.

### Слои (зависимости идут строго сверху вниз)

1. **Страницы/компоненты** (`src/pages`, `src/components`) — только UI, локальное состояние форм и клиентская валидация. Данные получают из сторов (`storeToRefs`), напрямую в `api`/`mocks` не ходят.
2. **Сторы** (`src/stores`) — состояние (`items`, `pagination`, `current`, `loading`, `error`) и оркестрация. Все методы асинхронные: `fetch*` пишут результат в состояние (ошибку — в `error`), мутации (`create/update/patch/delete`) пробрасывают `ApiError` странице и после успеха перезагружают список с последними фильтрами. В сторах нет ни мок-данных, ни логики «сервера».
3. **Сервисы** (`src/services`) — бизнес-процессы поверх api: `notificationService.notifyNewBook` рассылает SMS подписчикам авторов новой книги (вызывается из `booksStore.createBook`), `smsService` — эмуляция SMS Pilot (ключ из `VITE_SMS_PILOT_API_KEY`, по умолчанию `emulator`).
4. **API** (`src/api/*Api.js`) — «HTTP-клиент», один модуль на ресурс; сейчас поверх мок-базы. Чтобы подключить реальный бэкенд, заменяются только тела функций в `api/` (на `axios`), удаляется `src/mocks`. Отдельно: `serializers.js` (строки «БД» → схемы из `book.yaml`), `paginate.js`, `errors.js`.
5. **Моки** (`src/mocks`) — `data.js` (сиды) и `db.js` (изменяемая «БД» в памяти). Трогает их только `src/api`.

### Нюансы

- **Книги и авторы живут только в памяти** и сбрасываются при перезагрузке страницы. В localStorage хранятся только `token`/`user` (`authStore`) и подписки (`subscriptionsApi`).
- Книги в «БД» хранят `author_ids`, а авторов резолвят при чтении (`serializers.toBook`), поэтому переименование автора видно во всех книгах, а удаление автора снимает его с книг (книга может остаться без авторов — UI это учитывает).
- Расширения относительно `book.yaml` (нужны UI): `books_count` в элементах `GET /authors` и `booksApi.getYears()` для фильтра каталога.
- `authApi` — заглушка: подходят любые непустые логин и пароль. Гость = нет токена.
- `axios` в зависимостях и `.env.example` (`VITE_API_URL` и др.) заведены под будущую интеграцию, но пока не используются.

### Роутинг и права

`src/router/index.js`: все страницы грузятся лениво; единственный защищённый маршрут — `/books-manage` (`meta.requiresAuth`), guard редиректит гостя на `/login`, авторизованного с `/login` — на `/catalog`. Права на изменение/удаление (кнопки «Редактировать», «Удалить» и т. п.) скрываются в шаблонах через `v-if` по `authStore.isGuest` / `isAuthenticated` (в карточки флаг передаётся пропом `isGuest`); кнопка «Подписаться», наоборот, видна только гостям. Отдельного слоя проверки прав нет.
